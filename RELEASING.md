# Releasing

The only currently approved package channel is the isolated filesystem feed at `artifacts/packages`, configured for consumers by `eng/NuGet.local-consumer.config`. It is a development and exact-package validation channel, not an external publication or promotion target. No external NuGet publication is authorized from the temporary parent-repository folder.

The initial local prerelease was `0.1.0-alpha.1`. It was superseded during migration validation; immutable replacements start at `0.1.0-alpha.2`. Local artifacts are intentionally unsigned. Their integrity evidence consists of retained SHA-256 checksums, an SPDX 2.3 SBOM, and SLSA-shaped provenance generated by the repository tooling. External feed signing and promotion policy require a separate approval.

Source Link and source-control-manager queries are automatically enabled when GitHub Actions reports `GITHUB_REPOSITORY=onu-khatri/OnuObservability`. They stay disabled for ordinary local builds so a new or detached checkout can build before a remote and commit are present. A maintainer may enable Source Link in a complete independent checkout with `/p:OnuEnableSourceLink=true`; release validation must inspect the generated Source Link document before promotion.

A release must build and pack once, retain immutable hashes, validate API/package compatibility, generate SBOM and provenance evidence, run isolated-feed Web/Worker/MCP consumers, and record Windows/Linux results. Signing and external publication require an approved external feed, identity, credentials, and promotion decision. Stable promotion reuses the exact validated prerelease artifacts.
